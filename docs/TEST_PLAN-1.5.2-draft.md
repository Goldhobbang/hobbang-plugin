# HobbangEnhance 1.5.2 인게임 테스트 계획 (초안)

대장장이·무기 재제작(1.5.2)과 병렬 브랜치(`parallel/colossus-stability`: 콜로서스·센티넬 파편 정리, 안정화)를 합친 빌드 기준입니다.
껌냥이가 Paper 1.21.11 테스트 서버와 1.21.11 클라이언트에서 진행합니다. 두 작업을 합친 뒤의 jar·팩 zip과 `SHA1SUMS.txt`를 대조하고 시작합니다.

기록 항목: 버전·커밋, 보스, 모드(bossModels), 페이즈, 동작, FPS, `/mspt` 평균·최대, `/hobbang displays`, 영상·로그 시각.

## 1. 심연의 대장장이 새 모델 (1.5.2)

- [ ] 조립 연출이 끝난 뒤 판금 실루엣이 원본 디자인과 같다: 단조 투구와 청록 안광 슬릿, 가슴 보라·청록 V 코어, 갈색 가죽 앞치마, 오른손 적열 마그마 건틀릿, 3발가락 부츠.

- [ ] 용암 맥동 애니메이션(보스 망치 텍스처)이 끊기지 않는다.
- [ ] 페이즈 2(66%)·3(33%) 전환 연출과 대사가 나온다.

## 4. 사망 정리

각 보스를 생존 모드 플레이어가 실제 공격으로 처치합니다(`/kill`만으로는 경로가 다름).

- [ ] 연출 길이 뒤 처치 방송이 한 번 나오고, 플레이어 이름이 "누군가"가 아니다.
  기준: 대장장이 100틱(무릎 꿇기), 콜로서스 100, 센티넬 150, 와이번 110.
- [ ] 연출이 끝나면 보스바·히트박스·파츠·이펙트가 사라진다. 직전·직후 `/hobbang displays` 값을 기록한다.
- [ ] 전리품과 경험치가 한 번만 떨어진다.
- [ ] **사망 연출 중 언로드**: 보스를 처치하자마자 멀리 이동해(또는 텔레포트로) 청크를 언로드했다가 돌아온다.
  보스가 다시 살아나 있지 않고, 서버 로그에 `사망 연출 중 언로드됐던 보스 히트박스 정리`가 찍힌다.
- [ ] 서버 로그에 `finishDeath ...` 경고나 `death anim error` 가 없다. 있으면 전문을 기록한다.

## 5. 언로드·종료 시 display 잔여

- [ ] 보스 소환 직후(조립 중) 청크를 언로드했다가 돌아온다: 조립 파편이나 이중 파츠가 남아 있지 않다.
- [ ] 보스가 살아 있을 때 `/stop`으로 서버를 끈 뒤 다시 켠다: 보스가 다시 붙고, 바닥에 떠 있는 디스플레이가 없다.
  재시작 직후 `/hobbang displays` 값을 기록한다(보스 파츠 외에는 0이어야 함).
- [ ] 조립 연출 중이나 사망 연출 중에 `/stop` → 재시작해도 위와 같다.

## 6. 워밍업 / 첫 소환 스파이크

1. 서버를 새로 시작하고, 로그에서 `보스 모델 워밍업 완료 (... + 히트박스 경로)`를 확인한다(시작 후 약 2초 + 파츠 수/2 틱).
2. 워밍업 완료 후 10초 기다렸다가 `/mspt`를 기록한다(유휴 기준).
3. 첫 대장장이를 소환하고 바로 `/mspt`(5초·10초 최대)를 기록한다. 1.4.4에서 약 104ms 스파이크가 있었다.
4. 서버를 재시작해 3을 두 번 더 반복한다. 50ms를 넘는 최대 틱이 나오면 그 시각의 로그를 함께 남긴다.
5. 워밍업 로그가 나오기 **전에** 소환한 경우도 한 번 기록한다(워밍업 효과 비교용).

## 7. `/mspt` 측정 절차

같은 월드·위치·시야 거리·접속 인원(1명)에서, 1.4.4 → 1.5.2 순으로 비교합니다.

| 구간 | 측정 |
|---|---|
| 유휴 (보스 없음) | 시작 2분 뒤 `/mspt` 5s·1m |
| 보스별 조립 | 소환 직후 5s 최대 |
| 보스별 추적·보행 | 30초 동안 10s 평균·최대 |
| 대표 패턴 | 대장장이 내려찍기, 콜로서스 빔·수정 비, 센티넬 시간 정지·역행, 와이번 급강하·착지 |
| 사망 연출 | 연출 구간 10s 최대 |

합격 기준(AGENT_PROMPT §6): 보스전 평균이 1.4.4 대비 크게 늘지 않고, 50ms 넘는 스파이크가 없다.
파츠 수가 늘어난 보스(대장장이 16, 콜로서스 16, 와이번 36 디스플레이)는 평균값을 따로 표시한다.
