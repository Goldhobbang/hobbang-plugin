# 1.5.0 리그 (관절 세분화) + 와이번 박스 모델

범위: AGENT_PROMPT §2(관절 세분화)와 와이번 외형 개편. 움직임 고도화(§3)·패턴(§4)은 아직 안 했습니다 —
지금 Java 포즈는 기존 동작을 새 관절에 나눠 건 수준입니다. 서버·클라이언트는 실행하지 않았습니다.

## 와이번: 박스 모델 (`obj2mc/make_wyvern.py`)

- Meshy 복셀을 버리고 직접 설계한 박스 리그입니다. 형태는 `docs/reference/wyvern_style_ref.png`의 블록 드래곤 스타일,
  **색·무늬는 기존 Tempest Wyvern**을 따릅니다(남색 판 비늘, 노란 번개 맥, 금색 가시·뿔·발톱·배비늘).
  색은 원본 Meshy 텍스처에서 실측했고(`obj2mc/wyvern_palette.py`), 무늬는 절차적으로 그립니다(면마다 시드 고정이라 재실행해도 같음).
- 마디 하나 = 파츠 하나. 마디 박스는 부모 쪽으로 0.1 겹치게 만들어 회전해도 틈이 없습니다.
- 등가시는 22.5° 기울인 쐐기 박스 한 줄, 배 쪽은 금색 배비늘 띠, 머리는 주둥이/뿔 4개/눈/이빨 줄, 턱 분리.
- 날개: 상박 → 전완 → 손목에서 손가락뼈 3개가 부채꼴. 손가락 사이를 계단식 얇은 판 4장으로 채우고 바깥 판을 짧게 해서 끝단이 톱니처럼 들어갑니다. 손목에 발톱.
- element 회전 한계(단일 축 ±45°, 22.5° 단위)를 넘는 기울기(목 S자, 날개 펼침각, 다리 관절각)는 **파츠 rest 회전**,
  즉 item_display 변환으로 냅니다. 매니페스트에 `local_offset`·`rest_rot`가 들어가고 `BossModels.rig()` → `DisplayBoss.joint()`가 적용합니다.
- 비교 이미지: `docs/wyvern_redesign_compare.png` (레퍼런스 + 측면/정면/위/비행 자세).

Java 포즈(`WyvernBoss.poseModel`): 목·꼬리는 마디마다 위상을 늦춘 물결, 비행 중 목을 앞으로 뻗음, 날개는 어깨 퍼덕임 +
업스트로크에서 팔꿈치·손가락이 반쯤 접힘(뒤 손가락일수록 늦게 출렁), 착지 시 날개 접기, 비행 시 다리를 몸 아래로 접기, 턱 벌림.

## 나머지 3종: obj2mc 재분할

- `obj2mc/gen_humanoid_rigs.py`가 1.4.4의 6파트 config를 새 관절로 나눕니다(한 번만 적용).
- obj2mc 추가 기능: `joint_cap`(관절 pivot 주변 정육면체 범위의 이웃 파트 voxel을 양쪽에 복제 → 회전해도 틈 없음),
  `cap_with`(부모가 없는 다리를 골반과 캡), pivot의 `null` 좌표 자동 계산(그 관절면 근처 voxel의 중앙값),
  `sector` 영역(축 둘레 각도 쐐기).
- `obj2mc/pose.py`: 플러그인 `Rigid`와 같은 계산으로 파츠를 돌려 오프라인 렌더합니다(관절 틈 확인용).
  걷기/내려찍기/시전 자세로 세 보스를 렌더했을 때 관절 틈은 보이지 않았습니다.

- 업데이트 주기(`ANIM_INTERVAL` 3틱, 보간 3틱)와 "변환이 같으면 패킷 생략"은 그대로입니다.
- 서버 부하는 파츠 수에 비례합니다(Rigid 계산 + setTransformation). 대장장이·콜로서스가 약 2배, 와이번 1.6배.
  1.4.4에서 23파트 와이번이 fly 5s avg 2.3ms였으므로 여유는 있어 보이지만, **/mspt 실측이 필요합니다.**
- 클라이언트 쪽은 cuboid 총량이 줄었습니다(특히 와이번).

## 인게임에서 확인할 것

1. 와이번 rest 자세: 박스 리그는 rest 회전이 맞아야 형태가 나옵니다. 소환 직후 서 있는 자세가 비교 이미지의 측면도와 같은지.
2. 와이번 날개 접힘 방향(착지 `M_REST`에서 몸 옆으로 접히는지, 업스트로크에서 반쯤 접히는지), 좌우 대칭.
3. 와이번 히트박스 대비 크기: 모델 길이 약 9.3블록(머리~꼬리 끝), 몸통 중심 높이 약 1.56블록, 날개폭 약 9블록 (1.4.4는 길이 약 7.5, 날개폭 약 7.9). `make_wyvern.py`의 `SCALE` 하나로 조절. 히트박스(좀벌레 ×9)는 그대로.
4. 대장장이 무릎/팔꿈치 굽힘 방향, 망치가 오른손에 붙어 있는지. 콜로서스 사망 시 마디별로 떨어지는지.
5. 센티넬 진자 흔들림, 칼날이 팔보다 늦게 따라오는지.
6. 소환 조립 연출(AssembleAnim): 파츠 수가 늘어 날아오는 조각이 많아졌습니다. 순서·시간은 그대로.

## 알려진 한계

- 대장장이·콜로서스 렌더에서 작은 떠 있는 조각이 한두 개 보입니다(영역 분할 경계의 자투리 voxel).
- 콜로서스 팔은 결정이 많아 voxel 그대로라 cuboid 감소가 작습니다.
- 와이번 텍스처는 원본을 UV로 옮긴 것이 아니라 색을 실측해 다시 그린 것입니다. 번개 무늬 위치는 원본과 다릅니다.
- 블록 모델 폴백(bossModels off)은 건드리지 않았습니다(기존 코드 경로 그대로).
